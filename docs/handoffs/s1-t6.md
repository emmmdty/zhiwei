## 2. 前端架构（对齐 S1 后端 API）

- **api.ts**：same-origin fetch + credentials:include；mutation 统一带非空 Idempotency-Key + X-CSRF-Token；tenant context（X-ZhiWei-Organization / X-ZhiWei-Workspace）由 session 解析后全局注入；401 → SessionExpiredError；403 透传（server-driven，前端不硬判）。
- **session.tsx**：fetch /api/v1/me 读真实形状（principal/organizations/context/csrf_token）；角色经 GET /organizations/{id}/members 解析当前 principal 的 role_bindings（/me 不返回角色的唯一权威来源）；loading/unauthenticated/authenticated 三态。
- **App.tsx**：role-aware 导航（org_owner 显示 create/invite/remove，builder 显示 New agent，approver 显示 Approval queue，auditor 显示 Audit log）；bootstrap POST {organization_id}；workspace 创建 {workspace_id,name}；members 用 /api/v1/organizations/{id}/members；group 创建 POST /workspaces/{ws_id}/groups；remove member 有 Confirm removal 步骤；audit log 显示占位（S1 未交付 audit-events 端点）。

## 5. 完整 e2e 无法全绿的根因（根本性阻塞，不在 T6 GREEN 范围）

1. **T2 OIDC token exchange 缺陷（预存）**：`src/zhiwei/identity/oidc.py` `exchange_code` 的 authlib `fetch_token` 未显式传 `redirect_uri`，真实 Keycloak 下 callback 403 "login failed"（integration 用 FakeIdP/MockTransport 不校验该字段故 T2 全绿）。**这阻塞全部 13 个 e2e journey 的 signIn 步骤**。已实证：Keycloak 5 用户 + DB 5 principal 种子 + 后端 uvicorn + OPA + PG 全就绪，唯一卡点在此。修复需改 `src/zhiwei/identity/oidc.py`（白名单只读），待设计/验收方裁决后回 T2 RED 修订。
2. **S1 bootstrap 策略（N-1）**：后端 PEP 要求 bootstrap `count(input.actor.roles)==0`（authz.rego）——**已有任何 membership 的 principal 不能 bootstrap 新 org**。Owner journey 的第一步「create organization」对已播种 owner（有 org_owner 成员权）必然 403。这是 S1 语义（bootstrap 只服务首登），与 journey 的「owner 建 org」冲突。
3. **角色名脱节（N-2）**：bootstrap 写入角色 `"owner"`（commands.py），前端判 `"org_owner"`；PEP 有 LEGACY_ROLE_ALIASES 归一化而前端无——即使 bootstrap 成功，bootstrapped owner 前端 isOwner=false。
4. **bootstrap 后 tenant header 不刷新（N-3）**：App.tsx bootstrap 成功后未 refresh() session，新 org 的后续 mutation 携带陈旧/缺失 X-ZhiWei-Organization → 403。
5. **种子不可复现（N-4）**：PRINCIPAL_UUID/SEED_ORG_ID 只在 tenancy.spec.ts 一处，无 artifact 支撑（JIT 未实现，登录/邀请依赖外部种子）。
6. **group 不渲染（N-5）**：创建后前端不渲染 group 列表，journey 断言 `core-platform` 可见永不满足。
