## 契约草图

测试导入名就是最小公共 API：

```python
# domain.py
class EvalMode(StrEnum): ...
class SampleStatus(StrEnum): ...      # registered/running + completed/failed/refused/error
class RegisteredUnit(BaseModel):      # frozen; sample_id + unit_id
class SampleOutcome(BaseModel):       # frozen; canonical result_digest

# datasets.py / suites.py
class DatasetVersionSpec(BaseModel): ...   # frozen, digest/version/manifest bound
class EvalSuiteVersionSpec(BaseModel): ... # frozen, sorted unique registry

# runs.py — pure state plus PostgreSQL application service
class EvalRunState:                   # immutable transitions
    @classmethod
    def create(...): ...
    def record(...): ...
    def pause(...): ...
    def resume(...): ...
    def seal(...): ...

class EvalFoundationService:
    async def create(...): ...
    async def record_outcome(...): ...
    async def pause(...): ...
    async def resume(...): ...
    async def seal(...): ...
    async def seal_empty(...): ...
    async def verify_sealed(...): ...

# sealing.py
def build_sealed_artifact(...) -> tuple[SealedEvalArtifact, str]: ...
def verify_sealed_artifact(payload: Mapping[str, object], expected_digest: str) -> ...: ...
```

`EvalExecutor` 是 `@runtime_checkable Protocol`，`execute(RegisteredUnit)` 返回 terminal
`SampleOutcome`。Empty executor 确定返回 `FAILED + {"reason": "empty_executor"}`，无网络/子进程，不伪造
Agent 对话；Legacy executor 把 `CHECKSUMS.sha256` 每行注册为
`RegisteredUnit(sample_id=<path>, unit_id="checksum")`，成功校验返回具体 path/digest/verified result。
它只适配现有冻结资产并保持 registry 稳定排序，不迁移或重写语料。

`CreateEvalRunCommand.dataset_payload` 是需写入 ObjectStore 的 canonical dataset 内容；服务自己计算 digest，
不得接受调用方提供一个没有对象支撑的 digest。`SealEmptyCommand.test_report` / `seal(..., test_report=...)`
同理：先创建 `gate.test-report` object + manifest，再把 manifest id 与 digest 绑定进 seal；不能接受裸的
`test_report_digest`。

## 必须守住的不变量

1. Dataset/Suite version 与运行前 registry 冻结；同一 `(sample_id, unit_id)` 只能注册一次。
2. 结果只可写入已注册单位；非 terminal、重复或不同 payload 的二次写入 fail closed。
3. `completed | failed | refused | error` 都是完整分母内的 terminal；partial 不能 seal，只能以同一 registry
   resume；sealed 不能 resume。
4. record/pause/resume/seal 必须用同一个 EvalRun row lock 串行化，seal 取得锁后重新验证全部单位 terminal；
   写 Run terminal `succeeded`、EvalRun lifecycle、
   `eval.run.sealed` canonical event/outbox 与 artifact manifest。不要绕过 T4/T5 服务。
5. Sealed bytes 使用 T2 canonical encoding；digest 覆盖 mode、registry、所有 sample outcome、
   dataset/suite/code/config/schema digest、migration revision，以及 dataset/test-report manifest id + digest。
   验证必须依次从 dataset object、test-report object、seal object 和各自 PG manifest 独立复算；任一缺失、
   腐损、owner/digest 不匹配或 unknown schema/version一律拒绝。
6. 空 registry 可作为 S0 plumbing smoke（vacuously complete），但输出必须是真实 PG Run/EvalRun、event、
   outbox、dataset manifest 与 seal manifest，不能返回写死 JSON。
7. 所有 repo 查询显式带 organization/workspace；使用现有 RLS。不得读 `.env` 或调用 provider。
8. `assets lock` 默认等价 `--check`，漂移时非零且不写；只有显式 `--write` 才更新 lock；二者互斥。
   扫描范围沿用 Makefile 的 `evals/{novels,questions,risk}`，排除 lock 自身。
9. CLI 注册 `eval seal-empty|run|resume|seal`，无裸 traceback；mode 用 Enum 在进入执行前拒绝未知值。
   `seal-empty --check` 必须走真实 PG/Object/event/outbox 后再复核；legacy run 必须实际执行全部 checksum
   registry，再由独立 `eval seal <eval-run-id> --organization-id ... --workspace-id ...` 密封；run 输出必须
   返回这两个 tenant ID，后续命令显式恢复 RLS context。占位 help 命令或跨租户按 ID 扫描不能通过测试。
