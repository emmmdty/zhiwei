## 11. 三轮修复：真实 OPA 下 bootstrap 精确重放回归（RED `7a67289` / GREEN `29b06c2`）

### 11.1 回归与修复

**回归**：首建 201 后主体已是目标 org 的 owner member——二轮 Rego 的
`active_organization_id == null` 规则因此对**精确重放**（同 key 同 body）deny →
真实 OPA 下重放 403 而非 200（Rego 层探针实证：`first bootstrap: allow` /
`replay: default_deny:no_rule_matched`）。

**修复（设计裁决）**：单值 `active_organization_id` 改为权威、确定性的
`active_organization_ids: tuple[UUID, ...]`：

- Session resolver 从**全部权威 memberships**（org 与 workspace 作用域都计）生成
  active 组织 id 集合：去重 + 稳定排序；PolicyInput 序列化该集合，不信任 header/body；
- Rego `org/create` 只允许两类候选（kind=user + 无角色绑定 + 其一）：
  1. active 集合为空 → 首次 bootstrap（任意 target 进入命令层）；
  2. target ∈ active 集合 → 既有目标的重放候选——只放行进 application command，
     精确重放仍由 **owner-bound 幂等 scope `organization.create:<owner>` + request
     digest** 校验决定（不复制幂等逻辑进 Rego，不新建第二套权限矩阵）；
- target 不在集合内 → 禁止创建新组织（多组织用户不能 bootstrap 新 org）；
- `org/manage` 不放宽；集合字段缺失的原始 input（如 org/manage 直连）两个候选
  都未定义 → deny（fail closed，无求值错误）；
- 三个 router factory 对**显式 `policy_enforcer=None`** 增加组合期运行时守卫
  （TypeError，fail closed）；缺参数仍为 Python 原生 TypeError。

### 11.4 三轮独立审查（Subagent C，只读，未参与实现）

8 个重点面（租户接管/首次创建/精确重放/多组织确定性/digest 与幂等域/Rego 原始
input/router 守卫/审计语义）逐项对抗验证：**无 blocking 发现**。5 条 INFO：

1. Rego `count(roles)==0` 在线上路径是装饰性检查（bootstrap 请求不带 org header →
   principal-only 分支不填充绑定）：真实门禁是集合成员；且**带 org header 的重放会
   因绑定非空而 403 policy denied**（安全方向，但重放结果依赖 header 行为——bootstrap
   客户端必须不带 `X-ZhiWei-Organization`，已在 §11.5 记录）；
2. `actor.kind` 默认 USER、不读 principal 行（session 层拒绝非交互主体，纵深防御建议）；
3. bootstrap failed 审计的 FK 边界不可达（任何 failed 路径都要求目标 org 已存在）；
4. router 守卫是 `is None`（falsy 非 None 对象直连工厂会延迟到首请求才暴露——create_app
   恒注入真实 enforcer，不可达；按冻结契约「显式 None 组合期拒绝」落实）；
5. 空集合主体 POST 任意 UUID 的 201/403 差异是既有存在性 oracle（二轮同形状，非新披露）。

### 11.5 边界说明（不阻塞，登记备查）

- **bootstrap 幂等域仍为 per-org**（S0 `(org, ws, scope, key)` 键空间 + 三轮不改
  RLS/迁移）：同创建者跨目标 org 复用同一 key 属独立幂等域（S0 冻结语义）；同 key
  异 digest 的 409 契约经「预置异 digest claim」在真实 HTTP 路径冻结（API 表面无法
  以同 org 产生异 digest——digest = f(method, path, body)，body 仅 organization_id）；
- 重放请求必须**不带** `X-ZhiWei-Organization` header（带 header → 绑定非空 →
  403，安全方向）；
- 主体被移出 org 后（如自移除）active 集合为空：同 key 同 body 重放原 org → 200
  只读重放（无新行）；新 key → 403；同 key 异目标 → 按上述 per-org 域行为——不产生
  租户接管（目标必须不存在才会被创建，即全新 org，非受害者 org）。
