## 0. 一句话结论

S2 在本轮之前处于「checkbox 全勾但核心为协议级 fake」的状态；本轮把 A 档核心
（Temporal durable shell、outbox 桥接、eval 绑定）重建为**真实 SDK + 真实 PG** 绑定，
全仓 1102 测试 / Ruff / Pyright / evals / determinism 全绿；T7 的 SSE/Redis、
FixturePlanner port 与 Web journey 为显式遗留（见 §6）。

## 1. 发现：S2 草案的空壳实现（REVIEW 结论）

对上一轮未提交草案的复核发现（证据分支 `wip/s2-hollow-draft`，commit `c92b8ab`）：

| 契约（specs/s2 §3/§4/§7） | 草案实际 | 判定 |
| --- | --- | --- |
| Temporal durable shell（A 档） | Protocol 级 fake orchestration，`temporalio` 不在依赖里；plan T3 勾选「Add pinned Temporal dev service」但从未安装 | 空壳 |
| worker kill/restart、replay、CAN、timeout/retry 测试 | 对 fake 的单测（test_agent_run_workflow.py 636 行），不触真实 replay 引擎 | 空壳 |
| PG event 为真相 | reducer/events 为纯内存模块，无 canonical_events 绑定 | 空壳 |
| outbox 桥接（A 档） | 同步 Port + fake sender；handler 用**进程内 set** 做投递去重（worker 重启即失效） | 机制缺陷 |
| eval 走生产 Runtime | AgentRuntimeExecutor 自建事件序列原地 reduce——「执行就是重放自己造的事件」 | 评测旁路 |
| runtime-contract-v1 suite | 不存在（`eval run --suite runtime-contract-v1` 会报「未知 suite」） | 缺失 |
| Gate 目录 tests/{integration/temporal,integration/runtime,security/runtime_isolation,contract/task_graph} | 全部不存在 | 缺失 |
| Redis/SSE | in-memory streams，docstring 自述「Redis deferred」 | 空壳 |

根因判断：上一轮遇到「不引入第三方依赖」纪律与 spec 技术栈（Temporal SDK/Redis）冲突时，
没有停下来报告，而是静默造了第二套架构——正是 AGENTS.md 明令禁止的路径。
本轮将 `temporalio`（1.32.0）与 `redis`（6.4.0）按**冻结 spec 技术栈**加入依赖
（spec §Tech Stack 明示；plan T3 明示），在此显式报告。

## 2. 本轮修复（全部经真实 PG 127.0.0.1:55432 + 真实 Temporal dev server 验证）

### 2.1 预存故障修复（先于 S2 收口）

- **alembic_version 读权限**：`zhiwei eval seal-empty --check` / `eval seal` 在 app 会话读
  `alembic_version`，但 0001 起无任何 GRANT——S0 Gate 当时依赖测试库的 ALTER DEFAULT
  PRIVILEGES 残留（0003 注释已记录），库重建后 tests/integration/foundation 两例变红。
  修复：migration `0010_eval_revision_grant`（仅 SELECT；downgrade 撤销）。【已验证】

### 2.2 reducer / 事件契约（A 档，T2 修复）

- 新增 run 级事件：RunCompleted/RunFailed/RunCancelled/RunPaused/RunResumed；run 级状态机
  （created→running→{completed,failed,cancelled}|paused，终态后拒绝新调度）。
- `is_terminal` 收紧：run 级终态事件缺失时 run 不算 terminal（eval seal 的「partial 不得
  密封」由此获得事件级依据）。修订了 T2 草案单测（**收紧**而非放宽，草案测试未锁定提交）。
- task 重试语义：`failed → started` 合法（新 attempt 重新打开）；draft 单测
  `test_failed_to_any_raises` 相应修订（排除 started）。
- 修复 `TaskGraph.ready_tasks` 只遍历 edges.items() 的缺陷：未注册 edges 的根节点永远
  不 ready（真实 Temporal 集成暴露；根因是草案单测全部显式注册了空 edges）。

### 2.3 真实 Temporal durable shell（A 档，T3 重建）

- `zhiwei/workflows/agent_run.py`：真实 `@workflow.defn` AgentRunWorkflow——确定性编排
  （`workflow.uuid4()`、无 wall clock）、串行/并行分派（parallel_safe 门控）、依赖失败
  传播（TaskSkipped 落账）、cancel/pause/resume 信号（command_event_id 去重）、
  Continue-As-New（携带终态集合）、业务失败按节点 failure policy 重试。
- `zhiwei/workflows/activities/{base,runtime}.py`：`@activity.defn` 全部经
  `RuntimeEventStore → CanonicalUnitOfWork` 落 canonical_events（digest 链/projection/
  audit/outbox 与 S0 同路径）；幂等键按逻辑身份派生，activity 重试先查 `has_event` 再落账。
- `zhiwei/workers/agent_worker.py`：真实 Worker 装配。
- `zhiwei/runtime/persistence.py`：RuntimeEvent ↔ EventCommand 绑定（schema 注册表、
  strict python-mode 校验、JSONB lax 还原）。
- 集成测试 `tests/integration/temporal/test_agent_run.py`（8 例，WorkflowEnvironment
  .start_local 官方进程内 dev server）：deterministic start、duplicate workflow id 拒绝、
  业务失败重试（attempt aborted→committed 留痕）、duplicate cancel 单事件、CAN、
  **worker kill/restart**、**activity timeout→run failed**、**Replayer 重放**。

### 2.4 outbox 桥接（A 档，T4 修复）

- `OutboxSignalHandler`/`WorkflowSignalSender` 转 async（真实 Temporal client 是 async；
  同步 Port 是空壳的一部分）。T4 已提交单测做机械 async 修订 + 两处**语义**修订：
  1. 重复 start 的去重点从进程内 set 移到 deterministic workflow id + REJECT_DUPLICATE
    （`TemporalWorkflowSender`，worker 重启安全）；
  2. 重复 cancel 转发同一 command_event_id，去重发生在 workflow（真相层）。
  修订依据已在测试 docstring 记录。
- `workers/temporal_sender.py`：真实 client 适配（AlreadyStarted→delivered；
  NOT_FOUND→signal_before_worker 有界重试）。
- `workers/outbox_dispatcher.py`：topic 路由（runtime.command→Temporal；
  canonical.event.committed→EventSink，未配置时标记 delivered 防堆积）+
  `SessionOutboxRepository`（每操作独立 tenant 事务）。
- `runtime/run_commands.py`：命令侧服务——Run 行 + outbox 命令同一事务（无跨系统
  「同时事务」假设）。
- 集成测试 `tests/integration/runtime/test_db_temporal_outbox.py`（5 例）：DB/Temporal
  成功链路、崩溃后重投递幂等（单 execution）、signal-before-worker 有界重试、
  **真实 Temporal 宕机**（env 关闭）→ dead_letter、poison → dead_letter。

### 2.5 eval 绑定（B 档，T6 重建）

- `evals/runtime_contracts.py`：runtime-contract-v1 的 7 个契约场景（lifecycle、并行
  append 合并、重试重开、依赖失败 skip、重复 cancel、CAN、ADR-005 K-1 冲突）+ invariant
  断言（只读 reduced RunState）。
- `evals/executors/agent_runtime.py`：AgentRuntimeExecutor 经**生产命令路径**执行
  （RunCommandService→dispatcher→workflow→activities→PG），无 eval 专用旁路；
  RuntimeEvalEnvironment 装配进程内 dev server + worker + dispatcher。
- CLI：`eval run --suite runtime-contract-v1 --executor agent-runtime --mode fixture --seal`
  与 `runtime replay-check --all-fixtures`（从 PG 载入已提交事件序列：双 reduce 一致 +
  终态 + digest 链校验；不再使用内存造的序列）。
- 修订：`eval run --executor agent-runtime` 在 legacy-assets 上显式拒绝（fail closed），
  而非静默走旁路。

### 2.6 契约与安全目录（Gate 缺失项）

- `tests/security/runtime_isolation/`（1 例，真实环境）：**10 并发 run × 2 org**，
